### 附加功能

- **鼠标拖动的虚拟跟踪球（绝对映射）**：按住鼠标左键拖动时，把**按下点**与**当前点**分别投影到单位半球面，绕两点的叉乘轴转过两点夹角，再左乘到"按下时的姿态快照"上。因为是绝对映射而非增量累加，所以鼠标拖回按下点时物体姿态**精确复原**（增量累加因三维旋转不可交换而无法做到这一点）。另外叉乘轴是在相机坐标系下算出的，会先用视图矩阵旋转部分的转置换算回世界坐标，否则只有在接近前视图时方向才碰巧正确。
- **左键功能可切换**：按下**中键**便在"旋转物体"与"平移物体"之间切换，视口左上角的徽标与状态栏同步提示。平移模式下按键下的屏幕位移映射为世界位移：横向沿相机右向量、纵向沿相机上向量，每像素对应的世界长度按当前投影方式计算（正交取 `2·halfV/画布高`，其中 `halfV = camRadius·tan(fov/2)`；透视取 `2·tan(fov/2)·camRadius/画布高`），为绝对映射，拖回按下点即完全复原；拖动过程中侧栏的平移数字框实时回显。
- **平移/旋转/缩放三种基本变换的累积变换**：方向键（物体平移）+ 鼠标左键拖动（任意轴旋转）+ Z/C 或滚轮（整体缩放）互不覆盖，可任意叠加，最终合成为 `M = T·R·S`；空格键一键复位。
- **重新打磨的场景坐标系**：三色轴 + 圆锥箭头 + 正向实线/负向虚线 + 角落朝向 gizmo（框内带 HTML 矢量 X/Y/Z 标识，详见下文"场景坐标系"）；
- **顶点级漫反射着色**：把一盏方向光在生成顶点数据时就烘焙进顶点颜色，使方块六个面明暗分明、球体有平滑的体积明暗过渡、帽面的隆起与翻卷更立体。**不改着色器**，渲染管线与 alpha 淡出逻辑完全不受影响。
- **更直觉的鼠标相机操作**：右键拖动旋转相机、滚轮缩放物体（`Ctrl+滚轮` 推拉相机距离）、7 个视图预设一键跳转；
- **按住即连续旋转的相机键盘控制**：W/S/A/D 采用 `requestAnimationFrame` + 真实时间步长驱动，角速度恒定 `90°/s`，按住即匀速平滑旋转，松手或窗口失焦后自动停止。

### 复杂模型与层次动画（附加项 1、4）

- **Newell 茶壶**：32 个双三次 Bézier 补丁共 290 个控制点（控制点数据见 `teapot-data.js`），每个补丁按参数 `u/v` 各 8 等分细分为 128 个三角形，合计 4096 个三角形。求值时用 Bernstein 基函数的导数得到两个切向量、叉乘得法线，因此曲面明暗连续；原始数据以 Z 轴向上，生成时映射为世界 Y 轴向上，并按包围盒居中缩放到最大跨度 2.6。
- **环面纽结**：`(2,3)` 三叶结参数曲线 `C(t) = ((R+cos 3t)cos 2t, −sin 3t, (R+cos 3t)sin 2t)`，沿曲线取数值切线构造法平面、扫掠半径 `r=0.40` 的圆管（300 段 × 18 边 = 10800 个三角形），颜色沿曲线在青→紫之间渐变。曲线在 x/z 上并不对称，生成后统一按包围盒居中并缩放到最大跨度 2.6，避免旋转时绕偏离中心的点甩动。
- **Wavefront OBJ 导入**：工具栏"导入 OBJ"读入文本后解析 `v` 顶点与 `f` 面（支持 `v/vt/vn`、负下标、任意多边形按扇形三角化），逐三角形叉乘求面法线并烘焙 Lambert 明暗，再按包围盒居中缩放到 2.6；为防超大文件阻塞浏览器，三角形数上限 120000。导入的网格暂存于内存，切换到其它模型后再切回不会丢失，状态栏显示文件名。
- **导入模型的边线锐化**：在着色面之上再叠一层深色棱边，使面片结构与轮廓比纯色块锐利。只为每条"唯一棱边"生成一段线——同一条边会被相邻两个三角形各报告一次，按顶点下标对去重，保证每条边只画一次（立方体因此是 12 条棱边 + 6 条三角化对角线 = 18 条，而不是 36 条）。线色取基色的 30%，alpha 随边数在 0.28~0.62 之间自适应，网格越密线越淡，避免高面数模型被线网糊成一片深色。面与线共面，绘制前用 `polygonOffset` 把三角面沿深度方向后移一点，消除 z-fighting；深度测试照常保留，背面棱边被面遮挡，等效于隐藏线消除。
- **太阳系的层次建模与动画**：太阳（半径 1.5）、地球（0.55，公转半径 6.0）、月球（0.20，绕地半径 1.5），变换按父子关系逐级复合：

  ```
  太阳  M_sun   = M · R_y(sunSpin)
  地球  M_earth = M · T(公转位置) · R_y(earthSpin)
  月球  M_moon  = M · T(公转位置) · R_y(moonOrbit) · T(1.5,0,0) · R_y(moonSpin)
  ```

  地球公转 20°/s、自转 120°/s、月球公转 260°/s、自转 150°/s、太阳自转 16°/s（速度倍率为 1 时）。动画由 `requestAnimationFrame` 按真实时间步长推进（单帧上限 0.05 s），只在处于播放状态的层次模型中运行；两条轨道线在 XZ 平面内生成、绘制时关闭深度写入，因此能被星球正确遮挡。右侧"动画"面板（播放/暂停、速度 0~3 倍、重置）只在太阳系与齿轮组场景显示。
- **齿轮组的层次建模与动画**：三个齿轮在 XY 平面内绕各自的 Z 轴旋转，轴心间距严格等于两轮半径之和，相位按"齿对槽"排布，相邻轮转向相反：

  ```
  主动轮 A（20 齿）：θA = ω·t
  从动轮 B（15 齿）：θB = −θA·NA/NB
  从动轮 C（12 齿）：θC = −θB·NB/NC
  M_A = M·T(轴心A)·R_z(θA)，M_B = M·T(轴心B)·R_z(θB)，M_C = M·T(轴心C)·R_z(θC)
  ```

  子级转角由父级转角按齿数比换算，而不是各自用时间直接求角，这正是层次建模与"三个独立旋转的模型"的区别。齿轮几何由每齿 4 个轮廓点（齿根起 → 齿顶起 → 齿顶落 → 齿根落）绕 Z 轴扫掠成端面三角扇与齿侧四边形，并带伸出端面的轮毂轴；单个齿轮分别为 1176 / 936 / 792 个顶点，合计 2904 个顶点（968 个三角形）。整套齿轮组同样按包围盒居中、缩放到最大跨度 2.6。

## 技术要点

实现过程中有几处问题反复出现，我按 STAR（情境—任务—行动—结果）集中记在文末"遇到的问题与解决"里；这一节只保留需要展开推导、或容易望文生义的地方。

### 墨西哥帽高程函数（lec4 p.39）

平面坐标 `x = j·2/(nColumns-1)-1`、`z = i·2/(nRows-1)-1`，高程：

```
y = sin(πr)/(πr),  r = √(x²+z²) ≠ 0
y = 1,            r = 0
```

每个方格以 `A(i,j) → D(i+1,j) → C(i+1,j+1) → B(i,j+1)` 的逆时针顺序取 4 个顶点，展开为两个三角形 `A,D,C` 与 `A,C,B`。

### 相机球面漫游与 up 向量（lec6 p.45-49）

```
eye = r·( sinφ·sinθ , cosφ , sinφ·cosθ )
up  = ( -cosφ·sinθ , sinφ , -cosφ·cosθ )
```

其中 `θ` 为绕 Y 轴的方位角（A/D 键改变），`φ` 为相对 +Y 轴的仰角。该 `up` 向量恒为单位向量且与 `eye` 恒正交，因此相机正对 ±Y 极点时也不会与观察方向共线退化。默认 `theta=45°`、`phi=54.7356°`、`radius=15.5`，即 **等轴测视角**：`φ=arctan(√2)`、`eye=(8.95,8.95,8.95)`，三根正向轴在屏幕上等长且互成 120°，+Y 竖直向上、+X 指向右下、+Z 指向左下，能同时看清三个坐标轴。

**W/S 的旋转轴（严格绕世界 X 轴）**：`W`/`S` 把相机当作刚体绕世界 X 轴旋转——`eye` 与 `up` 同时左乘 `R_x(±Δ)`，旋转后再由新的视线方向反算 `(θ, φ)` 供界面显示；旋转后的 `up` 保存在 `camUp` 中，直到用户通过滑块或视图预设重新设定 `(θ, φ)`。正因为转轴是世界 X 轴本身，该轴在屏幕上的投影保持不动，其余景物（包括地平线）会绕它倾斜；若要让地平线始终保持水平，转轴就只能是相机自身的右向量，那就不再是绕世界 X 轴。A/D 走同一套 `R_y` 逻辑，不改变 `up` 的球面形式，等价于只改 `θ`。右键拖动复用这两个函数（横向 `R_y`、纵向 `R_x`），所以**世界 Y 轴不再被锁在垂直于屏幕的竖直平面内**：纵向拖动后它会获得屏幕横向分量，实际呈现为画面绕世界 X 轴的倾斜；拖动回起点时姿态精确复原。

### 变换矩阵的串联与传递

顶点着色器中按课件 lec6 p.53：`gl_Position = P·V·M·vPosition`；其中绘制坐标轴/gizmo 时不做 M 变换，用 `u_Flag` 区分（`P·V`）。`MVnew.js` 的 `flatten()` 会把行主序矩阵转置为 GLSL 要求的列主序后上传。

### 深度缓存

每帧清屏同时清除颜色与深度缓存（`COLOR_BUFFER_BIT | DEPTH_BUFFER_BIT`），否则旋转/缩放后残留的深度值会导致物体内部遮挡关系出错。

### 正交投影与透视投影的区别

| | 正交投影（平行投影） | 透视投影 |
| --- | --- | --- |
| 光线 | 平行，无共同出发点 | 从视点（眼睛）出发并向四周发散 |
| 尺寸 | 与距离无关，同一物体移到远近大小不变 | **近大远小**，比例随距离连续变化 |
| 平行线 | 投影后仍然平行 | 投影后收敛到**灭点**（消失点） |
| 矩阵特征 | `P[3][3] = 1`，裁剪坐标 `w ≡ 1`，**不做透视除法**；视野由 `left/right/bottom/top` 给出 | `P[3][2] = -1`，`w = -z_eye`，**要做透视除法**（这正是"近大远小"的来源）；视野由 `fov` 给出 |
| 适用 | 工程制图、CAD、需要保持比例的场景 | 接近人眼观感，游戏 / 漫游 / 建筑漫游 |

**怎么一眼区分**：在场景里把同一个物体沿视线前后移动——大小**完全不变**的是正交投影，会**近大远小**的是透视投影；或者看一组本应平行的线（例如立方体的棱），投影后仍然平行的是正交、向某点汇聚的是透视。本项目默认正交投影，按 `P` 键或点工具栏"投影"按钮切到透视，再推拉相机距离 `camRadius`，就能立刻看到这一差别。

> 需要说明的是，正交下推拉相机（`Ctrl+滚轮`）现在也会缩放画面——因为竖向半高取 `halfV = camRadius·tan(fov/2)`，否则平行投影下移动观察者根本看不出任何变化。但两者性质不同：正交下推拉只是**整体均匀缩放**，物体各部分的相对比例与平行关系都不变；透视下推拉则有**近大远小**，近处的棱比远处的长、平行棱向灭点收敛。

### 关于"看起来像左手坐标系"

`MVnew.js` 的 `lookAt` 是标准的 `gluLookAt` 实现（`v = normalize(at−eye)`、`n = normalize(cross(v, up))`、`u = normalize(cross(n, v))`，矩阵前三行依次为 `n、u、−v`），`ortho` / `perspective` 也都是标准 GL 实现，因此**世界坐标系是真正的右手系，矩阵链 `P·V·M` 不含任何镜像**。观感上容易觉得像左手系，有两个原因：

1. **默认等轴视角的朝向**：`θ=45°、φ=54.7356°` 时 `eye=(8.95, 8.95, 8.95)`，三根正半轴都朝向观察者，在屏幕上 `+Y` 朝上、`+X` 朝右下、`+Z` 朝左下，与"`+X` 朝右、`+Z` 朝屏幕外"的常见直觉不同；
2. **WebGL 裁剪空间（NDC）本身是左手系**：NDC 中 `+Z` 指向屏幕内部，这是图形 API 的内部约定，**不影响世界坐标系的手性**。

**自检方法**：切到前视图（`θ=0°、φ=90°`，`eye=(0,0,r)`，视线沿 `−Z`），此时屏幕向右为世界 `+X`、向上为世界 `+Y`、`+Z` 指向观察者——标准的右手系；用右手手指从 `+X` 弯向 `+Y`，拇指应指向 `+Z`。

## 场景坐标系

坐标轴、轴标签与角落 gizmo 三者都围绕"让使用者随时看清自己处在哪个方向"这一目标设计，具体做法与理由如下：

| # | 要点 | 做法与理由 |
| --- | --- | --- |
| 1 | 空间参照物 | 以贯穿场景的长坐标轴（半轴长 18.0，伸出画布外）作为空间参照，画面干净且不遮挡模型 |
| 2 | 三色轴贯穿原点 | X 红 `#e13b3b`、Y 绿 `#3ab54a`、Z 蓝 `#3a6ee1`；半轴长 18.0（约为画面竖向半高的 2 倍，轴会伸出画布外、成为贯穿全屏的空间参照），正向为实线 + **圆锥三角扇箭头**（24 段，轮廓圆润），负向取同色 55% 亮度并改为**虚线**（dash 0.90 / gap 0.60，步长 1.50 恰好把 ±18 分成 12 段），正负半轴一眼可分。因轴端在画面之外，等轴视角下轴呈现为贯穿屏幕的长线、箭头看不到；X/Y/Z 标识因此不标在画面边缘，而是画在右上角 gizmo 框内（见下一行） |
| 3 | X/Y/Z 标识 | 用 **HTML 覆盖层**（矢量清晰、缩放不糊），并且**放进右上角 gizmo 的取景框内**：每帧用 gizmo 自己的视图矩阵（只旋转不平移）与同一套 `ortho(±0.72)` 把世界点 `(0.70,0,0)/(0,0.70,0)/(0,0,0.70)` 投影成框内像素坐标写入 `style.left/top`，`ndc.z` 超出 `[-1,1]`（该轴指向相机背后、被近平面裁掉）时隐藏；像素位置再钳制在框内留白 8px，因此标识始终跟着轴端走、不越框 |
| 4 | 视图预设 | 提供 **7 个视图预设**（前 / 后 / 左 / 右 / 上 / 下 / 等轴测，工具栏一键切换并按当前 θ、φ 自动高亮），便于快速回到标准视角 |
| 5 | 几何构建时机 | 所有固定几何（坐标轴、gizmo）在场景构建阶段一次性生成静态顶点，之后不再重建 |
| 6 | 投影方式 | 正交 / 透视**显式可切**（`P` 键、工具栏按钮、`isOrth` 标志位），便于对比两种投影下同一场景的成像差异 |
| 7 | 相机参数调节 | 滚轮精细控制**物体缩放**（0.2~10.0）、`Ctrl+滚轮` 推拉相机距离 `camRadius ∈ [2, 40]`，`at` 恒为原点；正交投影的竖向半高取 `halfV = camRadius·tan(fov/2)`（默认 `15.5·tan30° ≈ 8.95`，横向随纵横比），使 Ctrl+滚轮与视野角滑块在正交下同样可见——否则"平行投影下沿视线方向平移观察者不改变成像"，推拉相机将毫无画面反应；坐标轴半轴长 18.0 约为默认 halfV 的 2 倍、会伸出画布成为贯穿全屏的参照；正交视见体的 `near/far` 取 `−200/+200` 的对称区间，相机距离调小后也不会出现近平面切掉场景的缺角 |

**渲染顺序（多 pass）**：①清屏 → ②物体（`TRIANGLES`，写深度）→ ③三色坐标轴（`depthMask(false)`，`depthFunc(LEQUAL)`，被物体正确遮挡）→ ④角落 gizmo 用 `SCISSOR_TEST` 圈出右上角 96×96 小方区、只清该区深度、改为“只旋转不平移”的视图矩阵与 `ortho(±0.72)` 绘制，随后恢复 viewport。

**角落朝向 gizmo**：绘制在 `(W-110, H-110, 96, 96)` 的小视口内（与页面右上角 `#gizFrame` 边框同位置同尺寸），相机方向随主相机联动、大小恒定，用于快速判断当前朝向；可由侧栏"显示"面板单独关闭。

**坐标轴与场景的层次**：坐标轴半轴长 18.0（约为默认正交竖向半高 8.95 的 2 倍，因此轴会伸出画布外，充当贯穿全屏的空间参照）。物体段顶点数随模型变化（方块 36 / 球 49152 / 墨西哥帽 600 / 茶壶 12288 / 环面纽结 32400 / 太阳系 8604 / 齿轮组 2904 / 导入 OBJ 随文件而定），固定段恒为 **294 + 150 = 444** 个顶点（绝对下标：坐标轴段 0~293、gizmo 段 294~443）；其中坐标轴段内是“线段 78 顶点（正向 3 条实线 + 负向 3 条各 12 段虚线）在前、圆锥 216 顶点在后”，gizmo 段内是“线段 6 顶点在前、圆锥 144 顶点在后”——**每个段内都是先线段后三角形**，因为一段内混有两种图元时无法用一次 `drawArrays` 画完。太阳系的物体段内部又按“两条轨道线 → 太阳 → 地球 → 月球”排列，齿轮组按“A → B → C”排列，各小段的起点与长度分别记录在 `solarSegments` 与 `gearSegments` 中，渲染时按天体/齿轮分别上传各自的模型矩阵。

## 顶点明暗（Lambert 漫反射，烘焙进顶点色）

各模型都采用同一套明暗模型，公式：`k = min(1, ambient + diffuse · max(0, n·l))`，顶点色 = 基色 × k（`ambient = 0.38`、`diffuse = 0.72`，方向光 `l` 取世界坐标下的右上偏前上方 `(0.600, 0.720, 0.350)`）。

| 模型 | 法线来源 | 效果 |
| --- | --- | --- |
| 方块 | 六个面的外法线常量（按 `quad()` 的首参映射） | 顶面/右面亮、底面/左面/后面暗，六面明暗分明 |
| 球体 | 球面顶点自身的单位向量（即归一化后的位置） | 单一色相的平滑体积过渡，通体圆润 |
| 墨西哥帽 | 由高程函数解析求导 `dy/dr = (πr·cos πr − sin πr)/(π r²)` 得到曲面法线 | 帽顶隆起与帽檐翻卷的明暗交界清晰 |
| 茶壶 | 补丁的两个 Bernstein 切向量叉乘 | 曲面明暗连续，壶身/壶嘴/壶把过渡平滑 |
| 环面纽结 | 扫掠圆截面的径向单位向量 | 圆管表面沿圆周方向有平滑的明暗带 |
| 太阳系 / OBJ | UV 球用球面法线，OBJ 用逐三角形面法线并叠加深色棱边 | 星球圆润；OBJ 呈分面（faceted）外观，棱边清晰 |
| 齿轮组 | 端面 ±Z、齿侧与轮毂径向、齿槽内壁径向 | 齿顶面最亮、齿侧依次变暗，轮齿轮廓清晰 |

因为色相（基色之比）在调制后保持不变，所以对颜色直观判断没有干扰；又因为明暗是**在顶点数据阶段烘焙**的，着色器、渲染管线、坐标轴等既有绘制逻辑全部不用改动。


## 遇到的问题与解决（STAR）

下面按情境（Situation）、任务（Task）、行动（Action）、结果（Result）记录七处典型问题，顺序与报告第 6 章一致。

### 1. 正交投影下推拉与视野角"数值在变、画面不动"

- **S**：切到正交投影后，拖动相机距离或视野角滑块，数值在变而画面纹丝不动，一度让人以为滑块没有绑定。
- **T**：让 `camRadius` 与 `fov` 在正交投影下也产生可见的画面变化，并与透视切换时保持尺度连续。
- **A**：定位到正交视见体的竖向半高被写死，而平行投影下沿视线平移观察者本就不改变成像。改为 `halfV = camRadius·tan(fov/2)`，并让正交矩阵与平移映射的 `worldPerPixel()` 共用同一个 `halfV`。
- **R**：两条滑块与 `Ctrl+滚轮` 在正交下均生效（15.5→20.63 时 `P[0][0]` 由 0.1020 变为 0.0767），投影切换不再跳变。

### 2. 右键纵向拖动方向相反、世界 Y 轴被锁在竖直平面内

- **S**：右键纵向拖动与横向方向相反；更奇怪的是无论怎么转，世界 Y 轴在屏幕上始终是一条竖线，没有任何横向分量。
- **T**：统一拖动方向，并让相机能真正绕到任意姿态。
- **A**：前者是纵向写成 `φ` 增大；后者是纵向只改 `φ`、再按球面公式重算 `up`，`up` 恒落在"世界 Y 轴与视线"决定的竖直平面内。改为与 W/S、A/D 共用刚体旋转：横向绕世界 Y 轴、纵向绕世界 X 轴，`eye` 与 `up` 一起转并写入 `camUp`。
- **R**：向下拖动 60 px 后 Y 轴屏幕方向由 `(0, 1)` 变为 `(−0.2212, 0.9752)`，反拖回起点时 `θ`、`φ`、`up` 精确复原。

### 3. 左键平移时数字框不回显、拖动偶尔中断

- **S**：左键平移物体时右侧平移数字框不跟着变；光标一出画布，拖动立刻断开。
- **T**：交互过程与面板显示始终同步，拖动全程连续。
- **A**：数字框改为在每帧 `syncUI()` 中回显（正在输入的框不覆盖）；`mousemove`/`mouseup` 从 `canvas` 移到 `window`。
- **R**：拖动不再中断，数字框实时跟随，手动输入不被抢占。

### 4. W/S 的旋转轴漂移

- **S**：早期只旋转视线方向、再按新 `(θ, φ)` 由球面公式重算 `up`，等效转轴会漂成一条斜轴，画面出现"地球自转"式的滚动。
- **T**：让 W/S 的转轴严格等于世界 X 轴。
- **A**：把 `eye` 与 `up` 当作刚体一起旋转，并保存旋转后的 `up`。
- **R**：90 次 1° 与一次 90° 的结果一致到 1e-13，绕行 40 步后 `eye` 的 x 分量漂移仅 2.3e-15。

### 5. 混合图元、正交下的标识可见性与滚轮事件

- **S**：坐标轴段与 gizmo 段内部同时含线段与圆锥三角形；gizmo 的 X/Y/Z 标识在正交投影下用 `w≤0` 判断完全失效；`Ctrl+滚轮` 会先触发浏览器页面缩放。
- **T**：三类图元都要正确绘制、标识不越框、滚轮由页面接管。
- **A**：段内记录"线段结束位置"，拆成先线段、后三角形两次 `drawArrays`；标识改为检查 `ndc.z ∈ [−1, 1]`；`wheel` 监听器 `preventDefault()` 并声明 `passive: false`。
- **R**：无图元错绘，标识始终跟随轴端且不越框，页面不再缩放。

### 6. UV 球两极出现暗斑

- **S**：太阳两极各有一块暗斑，从外部看像没有封闭。
- **T**：让球面真正闭合。
- **A**：极点处的四边形会退化为三角形，原实现按普通四边形展开，两极实际各有两个退化三角形。改为首尾两圈单独发三角形（北极 `(a,b,c)`、南极 `(a,b,d)`），三角形总数不变。
- **R**：暗斑消失，球面闭合，明暗连续。

### 7. 环面纽结绕原点旋转时"甩动"

- **S**：纽结旋转时明显绕着一个偏离几何中心的点摆动。
- **T**：让旋转中心与几何中心一致。
- **A**：`(2,3)` 曲线半径随参数变化，包围盒在 x、z 上并不对称；改为生成后按包围盒居中，并缩放到与其它模型一致的最大跨度 2.6。
- **R**：旋转平稳，与其它模型的尺度观感一致。
