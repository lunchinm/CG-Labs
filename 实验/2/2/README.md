### 附加功能

- **鼠标拖动的虚拟跟踪球（绝对映射）**：按住鼠标左键拖动时，把**按下点**与**当前点**分别投影到单位半球面，绕两点的叉乘轴转过两点夹角，再左乘到"按下时的姿态快照"上。因为是绝对映射而非增量累加，所以鼠标拖回按下点时物体姿态**精确复原**（增量累加因三维旋转不可交换而无法做到这一点）。另外叉乘轴是在相机坐标系下算出的，会先用视图矩阵旋转部分的转置换算回世界坐标，否则只有在接近前视图时方向才碰巧正确。
- **左键功能可切换**：按下**中键**便在"旋转物体"与"平移物体"之间切换，视口左上角的徽标与状态栏同步提示。平移模式下按键下的屏幕位移映射为世界位移：横向沿相机右向量、纵向沿相机上向量，每像素对应的世界长度按当前投影方式计算（正交取 `2·halfV/画布高`，其中 `halfV = camRadius·tan(fov/2)`；透视取 `2·tan(fov/2)·camRadius/画布高`），为绝对映射，拖回按下点即完全复原；拖动过程中侧栏的平移数字框实时回显。
- **平移/旋转/缩放三种基本变换的累积变换**：方向键（物体平移）+ 鼠标左键拖动（任意轴旋转）+ Z/C 或滚轮（整体缩放）互不覆盖，可任意叠加，最终合成为 `M = T·R·S`；空格键一键复位。
- **重新打磨的场景坐标系**：三色轴 + 圆锥箭头 + 正向实线/负向虚线 + 角落朝向 gizmo（框内带 HTML 矢量 X/Y/Z 标识，详见下文"场景坐标系"）；
- **顶点级漫反射着色**：把一盏方向光在生成顶点数据时就烘焙进顶点颜色，使方块六个面明暗分明、球体有平滑的体积明暗过渡、帽面的隆起与翻卷更立体。**不改着色器**，渲染管线与 alpha 淡出逻辑完全不受影响。
- **更直觉的鼠标相机操作**：右键拖动旋转相机、滚轮缩放物体（`Ctrl+滚轮` 推拉相机距离）、7 个视图预设一键跳转；
- **按住即连续旋转的相机键盘控制**：W/S/A/D 采用 `requestAnimationFrame` + 真实时间步长驱动，角速度恒定 `90°/s`，按住即匀速平滑旋转，松手或窗口失焦后自动停止。

## 技术要点

### 墨西哥帽高程函数（lec4 p.39）

平面坐标 `x = j·2/(nColumns-1)-1`、`z = i·2/(nRows-1)-1`，高程：

```
y = sin(πr)/(πr),  r = √(x²+z²) ≠ 0
y = 1,            r = 0
```

每个方格以 `A(i,j) → D(i+1,j) → C(i+1,j+1) → B(i,j+1)` 的逆时针顺序取 4 个顶点，展开为两个三角形 `A,D,C` 与 `A,C,B`。

### 相机球面漫游与 up 向量（lec6 p.45-49）

```
eye = r·( sinφ·sinθ , cosφ , sinφ·cosθ )
up  = ( -cosφ·sinθ , sinφ , -cosφ·cosθ )
```

其中 `θ` 为绕 Y 轴的方位角（A/D 键改变），`φ` 为相对 +Y 轴的仰角。该 `up` 向量恒为单位向量且与 `eye` 恒正交，因此相机正对 ±Y 极点时也不会与观察方向共线退化。默认 `theta=45°`、`phi=54.7356°`、`radius=15.5`，即 **等轴测视角**：`φ=arctan(√2)`、`eye=(8.95,8.95,8.95)`，三根正向轴在屏幕上等长且互成 120°，+Y 竖直向上、+X 指向右下、+Z 指向左下，能同时看清三个坐标轴。

**W/S 的旋转轴（严格绕世界 X 轴）**：`W`/`S` 把相机当作刚体绕世界 X 轴旋转——`eye` 与 `up` 同时左乘 `R_x(±Δ)`，旋转后再由新的视线方向反算 `(θ, φ)` 供界面显示；旋转后的 `up` 保存在 `camUp` 中，直到用户通过滑块、视图预设或右键拖动重新设定 `(θ, φ)`。正因为转轴是世界 X 轴本身，该轴在屏幕上的投影保持不动，其余景物（包括地平线）会绕它倾斜；若要让地平线始终保持水平，转轴就只能是相机自身的右向量，那就不再是绕世界 X 轴。A/D 走同一套 `R_y` 逻辑，不改变 `up` 的球面形式，等价于只改 `θ`。

### 变换矩阵的串联与传递

顶点着色器中按课件 lec6 p.53：`gl_Position = P·V·M·vPosition`；其中绘制坐标轴/gizmo 时不做 M 变换，用 `u_Flag` 区分（`P·V`）。`MVnew.js` 的 `flatten()` 会把行主序矩阵转置为 GLSL 要求的列主序后上传。

### 深度缓存

每帧清屏同时清除颜色与深度缓存（`COLOR_BUFFER_BIT | DEPTH_BUFFER_BIT`），否则旋转/缩放后残留的深度值会导致物体内部遮挡关系出错。

### 正交投影与透视投影的区别

| | 正交投影（平行投影） | 透视投影 |
| --- | --- | --- |
| 光线 | 平行，无共同出发点 | 从视点（眼睛）出发并向四周发散 |
| 尺寸 | 与距离无关，同一物体移到远近大小不变 | **近大远小**，比例随距离连续变化 |
| 平行线 | 投影后仍然平行 | 投影后收敛到**灭点**（消失点） |
| 矩阵特征 | `P[3][3] = 1`，裁剪坐标 `w ≡ 1`，**不做透视除法**；视野由 `left/right/bottom/top` 给出 | `P[3][2] = -1`，`w = -z_eye`，**要做透视除法**（这正是"近大远小"的来源）；视野由 `fov` 给出 |
| 适用 | 工程制图、CAD、需要保持比例的场景 | 接近人眼观感，游戏 / 漫游 / 建筑漫游 |

**怎么一眼区分**：在场景里把同一个物体沿视线前后移动——大小**完全不变**的是正交投影，会**近大远小**的是透视投影；或者看一组本应平行的线（例如立方体的棱），投影后仍然平行的是正交、向某点汇聚的是透视。本项目默认正交投影，按 `P` 键或点工具栏"投影"按钮切到透视，再推拉相机距离 `camRadius`，就能立刻看到这一差别。

> 需要说明的是，正交下推拉相机（`Ctrl+滚轮`）现在也会缩放画面——因为竖向半高取 `halfV = camRadius·tan(fov/2)`，否则平行投影下移动观察者根本看不出任何变化。但两者性质不同：正交下推拉只是**整体均匀缩放**，物体各部分的相对比例与平行关系都不变；透视下推拉则有**近大远小**，近处的棱比远处的长、平行棱向灭点收敛。

### 关于"看起来像左手坐标系"

`MVnew.js` 的 `lookAt` 是标准的 `gluLookAt` 实现（`v = normalize(at−eye)`、`n = normalize(cross(v, up))`、`u = normalize(cross(n, v))`，矩阵前三行依次为 `n、u、−v`），`ortho` / `perspective` 也都是标准 GL 实现，因此**世界坐标系是真正的右手系，矩阵链 `P·V·M` 不含任何镜像**。观感上容易觉得像左手系，有两个原因：

1. **默认等轴视角的朝向**：`θ=45°、φ=54.7356°` 时 `eye=(8.95, 8.95, 8.95)`，三根正半轴都朝向观察者，在屏幕上 `+Y` 朝上、`+X` 朝右下、`+Z` 朝左下，与"`+X` 朝右、`+Z` 朝屏幕外"的常见直觉不同；
2. **WebGL 裁剪空间（NDC）本身是左手系**：NDC 中 `+Z` 指向屏幕内部，这是图形 API 的内部约定，**不影响世界坐标系的手性**。

**自检方法**：切到前视图（`θ=0°、φ=90°`，`eye=(0,0,r)`，视线沿 `−Z`），此时屏幕向右为世界 `+X`、向上为世界 `+Y`、`+Z` 指向观察者——标准的右手系；用右手手指从 `+X` 弯向 `+Y`，拇指应指向 `+Z`。

## 场景坐标系

坐标轴、轴标签与角落 gizmo 三者都围绕"让使用者随时看清自己处在哪个方向"这一目标设计，具体做法与理由如下：

| # | 要点 | 做法与理由 |
| --- | --- | --- |
| 1 | 空间参照物 | 以贯穿场景的长坐标轴（半轴长 18.0，伸出画布外）作为空间参照，画面干净且不遮挡模型 |
| 2 | 三色轴贯穿原点 | X 红 `#e13b3b`、Y 绿 `#3ab54a`、Z 蓝 `#3a6ee1`；半轴长 18.0（约为画面竖向半高的 2 倍，轴会伸出画布外、成为贯穿全屏的空间参照），正向为实线 + **圆锥三角扇箭头**（24 段，轮廓圆润），负向取同色 55% 亮度并改为**虚线**（dash 0.90 / gap 0.60，步长 1.50 恰好把 ±18 分成 12 段），正负半轴一眼可分。因轴端在画面之外，等轴视角下轴呈现为贯穿屏幕的长线、箭头看不到；X/Y/Z 标识因此不标在画面边缘，而是画在右上角 gizmo 框内（见下一行） |
| 3 | X/Y/Z 标识 | 用 **HTML 覆盖层**（矢量清晰、缩放不糊），并且**放进右上角 gizmo 的取景框内**：每帧用 gizmo 自己的视图矩阵（只旋转不平移）与同一套 `ortho(±0.72)` 把世界点 `(0.70,0,0)/(0,0.70,0)/(0,0,0.70)` 投影成框内像素坐标写入 `style.left/top`，`ndc.z` 超出 `[-1,1]`（该轴指向相机背后、被近平面裁掉）时隐藏；像素位置再钳制在框内留白 8px，因此标识始终跟着轴端走、不越框 |
| 4 | 视图预设 | 提供 **7 个视图预设**（前 / 后 / 左 / 右 / 上 / 下 / 等轴测，工具栏一键切换并按当前 θ、φ 自动高亮），便于快速回到标准视角 |
| 5 | 几何构建时机 | 所有固定几何（坐标轴、gizmo）在场景构建阶段一次性生成静态顶点，之后不再重建 |
| 6 | 投影方式 | 正交 / 透视**显式可切**（`P` 键、工具栏按钮、`isOrth` 标志位），便于对比两种投影下同一场景的成像差异 |
| 7 | 相机参数调节 | 滚轮精细控制**物体缩放**（0.2~10.0）、`Ctrl+滚轮` 推拉相机距离 `camRadius ∈ [2, 40]`，`at` 恒为原点；正交投影的竖向半高取 `halfV = camRadius·tan(fov/2)`（默认 `15.5·tan30° ≈ 8.95`，横向随纵横比），使 Ctrl+滚轮与视野角滑块在正交下同样可见——否则"平行投影下沿视线方向平移观察者不改变成像"，推拉相机将毫无画面反应；坐标轴半轴长 18.0 约为默认 halfV 的 2 倍、会伸出画布成为贯穿全屏的参照；正交视见体的 `near/far` 取 `−200/+200` 的对称区间，相机距离调小后也不会出现近平面切掉场景的缺角 |

**渲染顺序（多 pass）**：①清屏 → ②物体（`TRIANGLES`，写深度）→ ③三色坐标轴（`depthMask(false)`，`depthFunc(LEQUAL)`，被物体正确遮挡）→ ④角落 gizmo 用 `SCISSOR_TEST` 圈出右上角 96×96 小方区、只清该区深度、改为“只旋转不平移”的视图矩阵与 `ortho(±0.72)` 绘制，随后恢复 viewport。

**角落朝向 gizmo**：绘制在 `(W-110, H-110, 96, 96)` 的小视口内（与页面右上角 `#gizFrame` 边框同位置同尺寸），相机方向随主相机联动、大小恒定，用于快速判断当前朝向；可由侧栏"显示"面板单独关闭。

**坐标轴与场景的层次**：坐标轴半轴长 18.0（约为默认正交竖向半高 8.95 的 2 倍，因此轴会伸出画布外，充当贯穿全屏的空间参照）。物体段顶点数随模型变化（方块 36 / 球 49152 / 墨西哥帽 600），固定段恒为 **294 + 150 = 444** 个顶点（绝对下标：坐标轴段 0~293、gizmo 段 294~443）；其中坐标轴段内是“线段 78 顶点（正向 3 条实线 + 负向 3 条各 12 段虚线）在前、圆锥 216 顶点在后”，gizmo 段内是“线段 6 顶点在前、圆锥 144 顶点在后”——**每个段内都是先线段后三角形**，因为一段内混有两种图元时无法用一次 `drawArrays` 画完。

## 顶点明暗（Lambert 漫反射，烘焙进顶点色）

三种模型都采用同一套明暗模型，公式：`k = min(1, ambient + diffuse · max(0, n·l))`，顶点色 = 基色 × k（`ambient = 0.38`、`diffuse = 0.72`，方向光 `l` 取世界坐标下的右上偏前上方 `(0.600, 0.720, 0.350)`）。

| 模型 | 法线来源 | 效果 |
| --- | --- | --- |
| 方块 | 六个面的外法线常量（按 `quad()` 的首参映射） | 顶面/右面亮、底面/左面/后面暗，六面明暗分明 |
| 球体 | 球面顶点自身的单位向量（即归一化后的位置） | 单一色相的平滑体积过渡，通体圆润 |
| 墨西哥帽 | 由高程函数解析求导 `dy/dr = (πr·cos πr − sin πr)/(π r²)` 得到曲面法线 | 帽顶隆起与帽檐翻卷的明暗交界清晰 |

因为色相（基色之比）在调制后保持不变，所以对颜色直观判断没有干扰；又因为明暗是**在顶点数据阶段烘焙**的，着色器、渲染管线、坐标轴等既有绘制逻辑全部不用改动。


## 验证

离线校验在 Node 中以 WebGL 桩加载模型数据与主程序，直接断言矩阵、顶点计数、映射关系与参数限位（18 项）；浏览器端在 HTTP 服务下逐项操作，读取矩阵元素与相机参数。

| 测试项 | 结果 |
| --- | --- |
| 顶点计数 | 方块 36 / 球 49152 / 帽 600；固定段 294 + 150 = 444 |
| 正交视见体动态性 | `camRadius` 15.5→20.63 时 `P[0][0]` 0.1020→0.0767；`fov` 60°→20° 时 0.0767→0.2510 |
| 右键方向 | 向下拖动 60 px 后 `φ` 54.7356°→36.7356° |
| 平移映射与回显 | `modelTrans = (3.70, −1.12, −1.58)`，侧栏同步显示 3.7 / −1.1 / −1.6 |
| 跟踪球绝对映射 | 拖出再拖回按下点，姿态精确复原（误差 1e-15 量级） |
| W/S 转轴 | 连续 40 次 −1.5° 后 `eye` 的 x 分量漂移 2.3e-15，反向可精确复原 |
| 渲染状态 | `gl.getError() = 0`，无控制台报错 |
