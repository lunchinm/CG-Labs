## 技术要点

### 墨西哥帽高程函数（lec4 p.39）

平面坐标 `x = j·2/(nColumns-1)-1`、`z = i·2/(nRows-1)-1`，高程：

```
y = sin(πr)/(πr),  r = √(x²+z²) ≠ 0
y = 1,            r = 0
```

每个方格以 `A(i,j) → D(i+1,j) → C(i+1,j+1) → B(i,j+1)` 的逆时针顺序取 4 个顶点，展开为两个三角形 `A,D,C` 与 `A,C,B`。

### 相机球面漫游与 up 向量（lec6 p.45-49）

```
eye = r·( sinφ·sinθ , cosφ , sinφ·cosθ )
up  = ( -cosφ·sinθ , sinφ , -cosφ·cosθ )
```

其中 `θ` 为绕 Y 轴的方位角（A/D 键改变），`φ` 为相对 +Y 轴的仰角。该 `up` 向量恒为单位向量且与 `eye` 恒正交，因此相机正对 ±Y 极点时也不会与观察方向共线退化。默认 `theta=45°`、`phi=54.7356°`、`radius=9.0`，即 **等轴测视角**：`φ=arctan(√2)`、`eye=(5.196,5.196,5.196)`，三根正向轴在屏幕上等长且互成 120°，+Y 竖直向上、+X 指向右下、+Z 指向左下，能同时看清三个坐标轴。

**W/S 的旋转轴到底是不是 X？** 只改变 `φ` 时，`eye` 的转动轴是 `(−cosθ, 0, sinθ)`——只有 `θ = 0°/180°`（前/后视图）时它才等于 ∓X 轴；默认等轴视角下它恰好等于屏幕水平轴，因此观感是"绕一根斜轴转"。本实现把 W/S 改成：先由当前 `(θ, φ)` 算出视线方向，按 `R_x(a)·v = (v0, v1·cos a − v2·sin a, v1·sin a + v2·cos a)` **严格绕世界 X 轴**旋转，再由旋转后的方向反算新的 `(θ, φ)`：

```
φ' = acos(y')
θ' = atan2(x', z')
```

`up` 随后按球面公式用新的 `(θ, φ)` 重新生成，因此相机不会累积滚转、地平线始终水平。A/D 改 `θ` 本身就精确等价于绕世界 Y 轴的旋转，无需换算。

### 变换矩阵的串联与传递

顶点着色器中按课件 lec6 p.53：`gl_Position = P·V·M·vPosition`；其中绘制坐标轴/网格/gizmo 时不做 M 变换，用 `u_Flag` 区分（`P·V`）。`MVnew.js` 的 `flatten()` 会把行主序矩阵转置为 GLSL 要求的列主序后上传。

### 深度缓存

每帧清屏同时清除颜色与深度缓存（`COLOR_BUFFER_BIT | DEPTH_BUFFER_BIT`），否则旋转/缩放后残留的深度值会导致物体内部遮挡关系出错。

### 正交投影与透视投影的区别

| | 正交投影（平行投影） | 透视投影 |
| --- | --- | --- |
| 光线 | 平行，无共同出发点 | 从视点（眼睛）出发并向四周发散 |
| 尺寸 | 与距离无关，同一物体移到远近大小不变 | **近大远小**，比例随距离连续变化 |
| 平行线 | 投影后仍然平行 | 投影后收敛到**灭点**（消失点） |
| 矩阵特征 | `P[3][3] = 1`，裁剪坐标 `w ≡ 1`，**不做透视除法**；视野由 `left/right/bottom/top` 给出 | `P[3][2] = -1`，`w = -z_eye`，**要做透视除法**（这正是"近大远小"的来源）；视野由 `fov` 给出 |
| 适用 | 工程制图、CAD、需要保持比例的场景 | 接近人眼观感，游戏 / 漫游 / 建筑漫游 |

**怎么一眼区分**：在场景里把同一个物体沿视线前后移动——大小**完全不变**的是正交投影，会**近大远小**的是透视投影；或者看一组本应平行的线（例如地面网格），投影后仍然平行的是正交、向某点汇聚的是透视。本项目默认正交投影，按 `P` 键或点工具栏"投影"按钮切到透视，同时把相机距离 `camRadius` 从默认 9 开始前后拉动，就能立刻看到这一差别。

### 关于"看起来像左手坐标系"

`MVnew.js` 的 `lookAt` 是标准的 `gluLookAt` 实现（`v = normalize(at−eye)`、`n = normalize(cross(v, up))`、`u = normalize(cross(n, v))`，矩阵前三行依次为 `n、u、−v`），`ortho` / `perspective` 也都是标准 GL 实现，因此**世界坐标系是真正的右手系，矩阵链 `P·V·M` 不含任何镜像**。观感上容易觉得像左手系，有两个原因：

1. **默认等轴视角的朝向**：`θ=45°、φ=54.7356°` 时 `eye=(5.196,5.196,5.196)`，三根正半轴都朝向观察者，在屏幕上 `+Y` 朝上、`+X` 朝右下、`+Z` 朝左下，与"`+X` 朝右、`+Z` 朝屏幕外"的常见直觉不同；
2. **WebGL 裁剪空间（NDC）本身是左手系**：NDC 中 `+Z` 指向屏幕内部，这是图形 API 的内部约定，**不影响世界坐标系的手性**。

**自检方法**：切到前视图（`θ=0°、φ=90°`，`eye=(0,0,r)`，视线沿 `−Z`），此时屏幕向右为世界 `+X`、向上为世界 `+Y`、`+Z` 指向观察者——标准的右手系；用右手手指从 `+X` 弯向 `+Y`，拇指应指向 `+Z`。

## 场景坐标系

参考自建 RayTracer 项目（Three.js）的网格 / 轴 gizmo 做法，并针对其相对 Unity 场景视图的不足做了 7 项优化：

| # | RayTracer 的做法 | 本次优化 |
| --- | --- | --- |
| 1 | 网格线单一密度、纯灰，远处密集如噪点 | **主次双密度网格**（次格 0.5、主线 2.0，覆盖 ±6 范围）+ 按到原点距离**逐线 alpha 淡出**（`a = clamp(1-\|t\|/6.5, 0.10, 1)`，主线 `rgb(0.36,0.40,0.47)` 与次线 `rgb(0.72,0.76,0.81)` 拉开层次），配合 `GL_BLEND` 实现，无需改着色器 |
| 2 | 主场景没有贯穿场景的彩色坐标轴 | **三色轴贯穿原点**：X 红 `#e13b3b`、Y 绿 `#3ab54a`、Z 蓝 `#3a6ee1`；半轴长 4.0，正向为实线 + **圆锥三角扇箭头**（24 段，轮廓圆润），负向取同色 55% 亮度并改为**虚线**（dash 0.24 / gap 0.16，步长 0.4 恰好把 ±4 分成 10 段），正负半轴一眼可分；网格的中心两条线仍保留、由轴覆盖绘制，既避免中心空洞又消除同深度双线 |
| 3 | gizmo 标签用 `Sprite` 贴图，缩放后模糊 | 轴标签改用 **HTML 覆盖层**（矢量清晰）：每帧把世界点 `(±L,0,0)/(0,±L,0)/(0,0,±L)` 经 `P·V` 投影为像素坐标写入 `style.left/top`；`clip.w<=0` 或位于相机平面之后时隐藏 |
| 4 | gizmo 只作被动指示、无视图预设 | 新增 **7 个视图预设**（前 / 后 / 左 / 右 / 上 / 下 / 等轴测，工具栏一键切换并按当前 θ、φ 自动高亮） |
| 5 | 网格几何随相机距离反复重建（GC 抖动） | 网格**一次性生成静态顶点**，不做重建 |
| 6 | 只有透视投影 | 正交 / 透视**显式可切**（`P` 键、工具栏按钮、`isOrth` 标志位） |
| 7 | 相机距离由 OrbitControls 的固定区间硬性决定 | 滚轮精细控制**物体缩放**、`Shift+滚轮` 推拉相机距离 `camRadius ∈ [2, 40]`，`at` 恒为原点；正交投影下竖向视野固定 ±6.5（横向随纵横比），保证 ±6 网格在俯视图下不被裁切且留有余量；正交视见体的 `near/far` 取 `−200/+200` 的对称区间，因为"平行投影下沿视线方向平移观察者不改变成像"，相机距离调小后也不会出现近平面切掉网格后半部的缺角 |

**渲染顺序（多 pass）**：①清屏 → ②物体（`TRIANGLES`，写深度）→ ③地面网格、再画三色轴（`depthMask(false)`，`depthFunc(LEQUAL)`，被物体正确遮挡且轴覆盖网格中心线）→ ④角落 gizmo 用 `SCISSOR_TEST` 圈出右上角 96×96 小方区、只清该区深度、改为"只旋转不平移"的视图矩阵与 `ortho(±0.72)` 绘制，随后恢复 viewport。

**角落朝向 gizmo**：绘制在 `(W-110, H-110, 96, 96)` 的小视口内（与页面右上角 `#gizFrame` 边框同位置同尺寸），相机方向随主相机联动、大小恒定，用于快速判断当前朝向；可由侧栏"显示"面板单独关闭。

**坐标轴与网格的层次**：网格 half=6.0 覆盖 ±6 范围，坐标轴半轴长 4.0，中心两条网格线仍绘制并被轴覆盖，因此不存在"轴外空白"。物体段顶点数随模型变化（方块 36 / 球 49152 / 墨西哥帽 600），固定段恒为 **282 + 100 + 150 = 532** 个顶点（绝对下标：坐标轴段 0~281、网格段 282~381、gizmo 段 382~531）；其中坐标轴段内是"线段 66 顶点（正向 3 条实线 + 负向 3 条各 10 段虚线）在前、圆锥 216 顶点在后"，gizmo 段内是"线段 6 顶点在前、圆锥 144 顶点在后"——**每个段内都是先线段后三角形**，因为一段内混有两种图元时无法用一次 `drawArrays` 画完。

## 顶点明暗（Lambert 漫反射，烘焙进顶点色）

三种模型都采用同一套明暗模型，公式：`k = min(1, ambient + diffuse · max(0, n·l))`，顶点色 = 基色 × k（`ambient = 0.38`、`diffuse = 0.72`，方向光 `l` 取世界坐标下的右上偏前上方 `(0.600, 0.720, 0.350)`）。

| 模型 | 法线来源 | 效果 |
| --- | --- | --- |
| 方块 | 六个面的外法线常量（按 `quad()` 的首参映射） | 顶面/右面亮、底面/左面/后面暗，六面明暗分明 |
| 球体 | 球面顶点自身的单位向量（即归一化后的位置） | 单一色相的平滑体积过渡，取代框架原有的青/品红/绿拼色噪点 |
| 墨西哥帽 | 由高程函数解析求导 `dy/dr = (πr·cos πr − sin πr)/(π r²)` 得到曲面法线 | 帽顶隆起与帽檐翻卷的明暗交界清晰 |

因为色相（基色之比）在调制后保持不变，所以对颜色直观判断没有干扰；又因为明暗是**在顶点数据阶段烘焙**的，着色器、渲染管线、坐标轴/网格的 alpha 淡出逻辑全部不用改动。
